# 과학중점 과학실 예약 · 이수시간 사이트

과학정보부 과학실무사 업무용 웹사이트입니다. 빌드 도구 없이 HTML/CSS/JS만으로 동작하며, GitHub Pages에 그대로 올릴 수 있습니다.

## 기능

| 구분 | 학생 (로그인 없음) | 과학실무사 (관리자 로그인) |
|---|---|---|
| 일정 캘린더 | 승인된 실험실 사용(신청 승인 시 자동 등록), 과학행사 일정 보기 | — |
| 실험실 사용 신청 | 학교 A4 양식 3종(신청서·시약·시액 조사서·실험 계획서) 작성 → PDF 저장 / 온라인 제출 | 승인/반려 + 메모, 겹침 경고, 제출된 신청서 PDF 저장 |
| 물품 구입 신청 | 학교 A4 양식(사이트 주소 칸 포함) 작성 → PDF·엑셀 저장 / 온라인 제출 | 진행 상태 변경(준비중·추후예정·배송완료·보류·구매취소·인계완료), 여러 팀 선택 → 학교 '물품 신청내역' 형식 엑셀(+사이트 주소 열)로 내보내기 |
| 신청 결과 조회 | 팀명(동아리명)으로 승인/반려와 실무사 메모 확인 (이름·학번은 표시 안 됨) | — |
| 행사 일정 | 홈 화면 공지에 "예정 / 완료 / 취소" 표시 | 일정 등록, 상태 즉시 변경 (날씨 대응), 엑셀 양식으로 일괄 등록 |
| 이수시간 | 학번 5자리로 누적 시간·내역·40시간 달성률 확인 | 학번 여러 개 붙여넣기로 일괄 부여, 엑셀 양식으로 일괄 등록, 전체 현황 |

## 디벗 (학생 태블릿)

- **학생 (메뉴 '디벗')**: 허용된 앱·사이트 목록 확인, 앱·사이트 허용 신청, 학교 구글 계정 비밀번호 재설정 신청. 결과는 '신청 결과 조회'에서 학번으로 확인.
- **관리자 → 디벗 관리**
  - 기기 현황: 기존 기기대장 엑셀 가져오기, 학년별 배정·예비·수리·분실 대수, 회수(→예비)·전입생 배정, 기기별 변경 이력, 구글 진급 CSV로 학번 일괄 변경, 기기대장 엑셀 내려받기
  - 비밀번호 요청: 임시 비밀번호 생성 → 구글 관리 콘솔에서 재설정(로그인 시 변경 체크) → AMA 메시지로 학생 디벗에 전송 → 처리 완료. **임시 비밀번호는 어디에도 저장되지 않음**
  - 앱·사이트 신청: 같은 앱 신청을 묶어 처리, 허용된 목록 관리(학생에게 공개)
  - 신입생 계정 CSV: 명단(학번·이름) → 구글 일괄 업로드 CSV(UTF-8) + 계정 명렬표. 브라우저 안에서만 처리하고 저장하지 않음
- 기기대장(이름·시리얼·계정)과 신청 원본은 관리자만 볼 수 있습니다. 학생 실명 엑셀·CSV는 이 저장소에 올리지 않습니다.
- AMA 기기 일괄등록 양식은 양식 파일을 받은 뒤 추가 예정.

## 서명

- 신청서의 (인)·(자필서명) 칸을 누르면 서명 패드가 열립니다. 휴대폰은 손가락, PC는 마우스로 서명합니다.
- 실험실 신청서·물품 구입 신청서 모두 **신청자 서명과 지도교사 서명**이 있어야 온라인 제출됩니다. 서명은 PDF에도 찍힙니다.
- 관리자 화면에는 서명이 함께 보이고, **'지도교사 확인함'**을 체크해야 승인 버튼이 눌립니다(메신저·전화 등으로 지도교사에게 확인). 반려는 체크 없이도 됩니다.
- 서명 이미지는 관리자만 볼 수 있고, 학년도 정리 때 신청 기록과 함께 삭제됩니다(엑셀 백업에는 들어가지 않음).

## 학년도 운영

- 학년도는 **3월 1일**에 바뀝니다. 모든 신청·이수시간·일정은 학년도별로 따로 저장되고, 관리자 화면 위쪽에서 학년도를 골라 봅니다.
- 이수시간은 학년도마다 0시간부터 다시 쌓입니다(같은 학번이라도 학년도가 다르면 별도 기록).
- 학년도가 끝나면 **관리자 → 학년도 정리** 탭에서 지난 학년도를 고르고 ① 엑셀로 백업 → ② 삭제합니다. 진행 중인 학년도는 삭제할 수 없습니다.
- 캘린더·홈은 화면에 보이는 기간의 일정만 불러오므로 기록이 쌓여도 무료 사용량 안에서 동작합니다.
- 주소 끝에 `?demo=1`을 붙이면 실제 데이터를 건드리지 않는 데모 모드로 열립니다(연습·테스트용).

## 파일 구성

```
index.html        페이지 뼈대 (메뉴)
css/style.css     디자인
js/config.js      ★ Firebase 설정, 학교명, 실험실 목록, 목표시간 등
js/store.js       데이터 저장 (Firebase 또는 데모용 브라우저 저장)
js/forms.js       A4 양식, PDF 저장, 엑셀(품목내역) 저장
js/app.js         각 화면
firestore.rules   ★ 보안 규칙 (Firebase 콘솔에 붙여넣기)
```

`js/config.js`의 `apiKey`가 비어 있으면 **데모 모드**로 동작합니다(데이터는 그 브라우저에만 저장). `index.html`을 더블클릭해서 바로 볼 수 있습니다.

## Firebase 연결 (관리자 계정)

1. https://console.firebase.google.com 에서 프로젝트 만들기 (Google Analytics는 꺼도 됨)
2. **빌드 > Firestore Database** → 데이터베이스 만들기 (위치: `asia-northeast3 (서울)`, 프로덕션 모드)
3. **Firestore > 규칙** 탭에 `firestore.rules` 내용 붙여넣고 게시
4. **빌드 > Authentication** → 시작하기 → 로그인 방법에서 **이메일/비밀번호** 사용 설정
5. **Authentication > 사용자** → 사용자 추가 (실무사 이메일/비밀번호) → 생성된 **사용자 UID** 복사
6. **Firestore > 데이터** → 컬렉션 `admins` 생성 → 문서 ID에 위 UID 붙여넣기 → 필드 아무거나 하나 (예: `name` = `과학실무사`)
7. **프로젝트 설정(톱니바퀴) > 내 앱 > 웹 앱 추가(</>)** → 표시되는 `firebaseConfig` 값을 `js/config.js`에 붙여넣기
8. **Authentication > 설정 > 승인된 도메인**에 `<GitHub아이디>.github.io` 추가

> 관리자 계정을 늘리려면 5~6번만 반복하면 됩니다. 학생은 계정이 필요 없습니다.
> 무료(Spark) 요금제로 충분합니다 (하루 읽기 5만 회 / 쓰기 2만 회).

## GitHub Pages로 공개

1. GitHub에서 새 저장소 만들기 (예: `science-lab`, Public)
2. 이 폴더의 파일을 모두 업로드 (Git이 없으면 저장소 화면의 **Add file > Upload files**로 끌어다 놓기)
3. 저장소 **Settings > Pages** → Source: `Deploy from a branch`, Branch: `main` / `(root)` → Save
4. 1~2분 뒤 `https://<GitHub아이디>.github.io/science-lab/` 주소로 접속

## 학번 규칙

5자리: 학년(1) + 반(2) + 번호(2). 예) `20315` = 2학년 3반 15번. 다르면 `js/store.js`의 `parseSid`를 수정합니다.
